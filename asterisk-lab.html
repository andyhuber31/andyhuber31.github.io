From a switch port to a working call

I connected a Yealink T33-series IP phone to my Cisco 3750 and wanted to give it something useful to call. I built a local phone system with Asterisk on a Debian VM and used MicroSIP on my Windows laptop as the second phone. No external calling provider was involved.

How the pieces fit

The desk phone uses voice VLAN 124. The PBX is on VLAN 62. My laptop connects over Wi-Fi. Both phones register with Asterisk, which uses the internal dialplan to connect the extensions.

What clicked: An IP address makes the phone reachable. A SIP account registers it with the PBX. The dialplan determines what happens when I dial an extension.

What I configured

  1. Built from source. Debian’s configured repositories had no Asterisk package candidate. I installed the build dependencies, configured the source with bundled PJPROJECT, compiled it, and verified version 22.12.0.
  2. Created the SIP accounts. Defined endpoints, authentication objects, and addresses of record for 1001 and 1002 in pjsip.conf. The account definitions share a template and allow G.711 μ-law audio.
  3. Added a small dialplan. Defined calls to 1001 and 1002 and a 600 echo test in the internal context.
  4. Set up the service. Created a dedicated Linux service account and a systemd unit, then enabled startup at boot.
  5. Registered and tested. Registered the Yealink and MicroSIP with the PBX, tested audio, and rebooted the VM to check recovery.

Troubleshooting along the way

Installed, but “command not found”

The installation completed, but my regular user could not find asterisk. Running /usr/sbin/asterisk -V verified the binary. The issue was the command search path.

The phone answered ping, but its webpage would not open

PowerShell tests showed TCP 80 failed while TCP 443 succeeded. Using the phone’s HTTPS address brought up the administration page. That separated IP reachability from the availability of a particular service.

One call direction initially failed

A phone-to-laptop call worked first. I attached to the Asterisk console and retried the opposite direction; the log showed 1001 ring, answer, and join the bridge. The retry succeeded, but I did not establish the cause of the first failure.
